## 2. 几何与证据口径

真实原NMS输入、原分数、层标识和保留索引决定集合。主关系须满足同层、保留框原分数更高或完全同分、原坐标CPU float32相互IoU严格>0.7。等于阈值不满足；没有重新排序或运行CPU NMS。

float64原坐标几何和按层偏移后float32几何为单列诊断。仅诊断满足的行不并入主关系数；1e-6只标记阈值附近，不放宽0.7或0.75。按层偏移是本地数值敏感性重建，不是原CUDA内部逐次抑制记录。跨层偏移后重叠消失是设计行为，不计作数值不稳定。

保留集合采用原NMS全部输出：目录共7024项，包含730个后来被150预算截掉的框，最大输出位置244（0起始）。主关系中的相关框最终都通过预算，不能由此推出全val没有预算损失；Day04的2个纯预算丢失事件不属于本轮NMS丢失队列。

每个被删好框都找到主关系：108个候选对应1个可能保留框，11个对应2个，合计130条。未解释GT为0，主关系同分GT为0；定义范围内没有同层同分、1e-6阈值附近或几何判定分歧项，诊断独有关系为0。主关系最小相互IoU为0.7007054686546326。这些结论限定于本事件队列，不能推广到全部候选。

所有关系统一称“可能相关的保留框”。原索引证明删除阶段及保留集合；坐标、层和分数证明关系条件；它们没有证明原GPU实际由哪个框抑制了哪个框。即使唯一可能关系也不是直接抑制记录，本轮未实现独立贪心NMS归因。

## 3. 模型和场景各发生了什么

两模型都出现了“进入NMS的好框全部删除、附近存在同层高分重叠保留框”的模式，没有表现为Fusion专有的规则现象。

|场景|IR丢失／NMS前已覆盖GT|Fusion丢失／NMS前已覆盖GT|
|---|---:|---:|
|整体|24/326（7.36%）|34/321（10.59%）|
|03|2/80（2.50%）|10/73（13.70%）|
|08|9/99（9.09%）|9/100（9.00%）|
|13|6/97（6.19%）|5/98（5.10%）|
|17|7/50（14.00%）|10/50（20.00%）|

03中Fusion丢失更多，08数量相同，13反而IR多1项，17中Fusion多3项。这些自身条件率的风险分母不同，不能直接当作同GT公平配对。

利用全图GT，IR的0/24、Fusion的0/34个事件存在“主关系保留框与其他GT的IoU高于指定GT”的情况。当前没有为“相关保留框转而定位其他已标注GT”提供支持；不能据此确认真实语义归属或排除所有混淆。完整其他GT重叠在gt_overlap_audit.csv。

## 4. 共同风险GT配对后差异是否仍在

全部416GT的NMS丢失状态：两模型都丢失10、仅IR丢失14、仅Fusion丢失24、均未发生NMS丢失368。最后一类包含不处于风险中的GT，不能统称成功保留；all_gt_pairing.csv单独保存not_at_risk、lost、still_covered状态。

两模型在NMS前都覆盖的共同队列为297GT：IR丢失21/297（7.07%），Fusion丢失30/297（10.10%）。两者都丢失10、仅IR丢失11、仅Fusion丢失20、均保持覆盖256。同一分母下Fusion多9项，约3.03个百分点；描述性差异仍存在，不是因果效应或显著性检验结论。

|共同风险范围|GT数|IR丢失|Fusion丢失|两者都丢失|仅IR丢失|仅Fusion丢失|Fusion−IR净差|
|---|---:|---:|---:|---:|---:|---:|---:|

共同风险相同仍未控制候选数量、层支持、分数和几何差异，不能将配对净差直接归因为融合机制。

## 5. 选择条件自然带来什么

本队列要求NMS后所有保留框对指定GT IoU<0.75，而被删好框≥0.75，所以相关保留框对指定GT定位更差部分由队列定义直接约束；关系又筛选更高分或同分。不能把其高比例当作所有候选分数质量关系或独立根因证明。

按层NMS规则本就倾向于留下高分重叠框，找到相容关系首先说明几何数据与规则相容，不是发现Fusion独有缺陷。真正有助于后续的信息是共同风险同GT上的非对称丢失、场景集中性，以及未解释／同分／数值敏感／其他GT重叠的检查结果；这些仍未说明NMS前为什么形成该候选结构。
