# Week11 Day04 · 全验证集 RoI 诊断范围核查

**已完成范围核查。** 正式清单为 [run02 的 scope.json](outputs/full_val_scope_run02/scope.json)。共 150 张验证图、416 个有效 `person` 标注。IR 和 Fusion 都使用这套标注，共 300 个模型×图片项。今天只读取文件、整理标注和核验历史捕获，完整模型前向、checkpoint 加载及独立 NMS 重放均为 0。

## 为什么做这一步

Day02 和 Day03 在两个选定 Fusion 案例里都看到最高分框先移除了所有达标框。要判断这一现象涉及多少验证目标，需要把成功和失败的目标一起统计。提前固定样本、阶段以及计算口径，同样的结果就能复查，也能减少看完结果后才调整样本或统计规则的偏差。全验证集统计仍是对这套数据的探索性描述。

## 核对结果

- 逐项核对原始 manifest、150 张 RGB、150 张 IR 和 150 份 XML 的 SHA256，均与 Week09 的记录相符。用项目原标注解析器重新读取 XML，核对每个场景和每张图的标注编号。两个模型的 416 项 GT 身份均与 Week09 对齐。
- 冻结了每张图的文件路径、SHA256、场景、原验证集顺序和 Letterbox 后的 GT 坐标，也冻结了两个模型的 checkpoint SHA256、完整配置和状态摘要。
- 逐份核对 `030078`、`030129` 的 IR/Fusion 捕获。4 份都能从实际 RPN 输出追到 RoI 行、分数与小框筛选、原 NMS 索引和完整最终输出，且与冻结的全部 GT 坐标精确一致。`030129/IR` 的原捕获没有单列 GT 标签，使用已核对的 `person` XML 标签，并保留这一来源说明。
- 首轮预检将 `030129/IR` 的 `[(640, 640)]` 和 `[[640, 640]]` 当成不同尺寸。核对原值后统一为数值对，重跑只读预检通过。保留 [run01 缺口记录](outputs/full_val_scope_run01/scope.json)。

## 固定统计口径

1. 使用本地 CPU、原 IR/Fusion 权重、原预处理和推理配置。RPN 分数阈值 0.05、NMS 阈值 0.7，使用原 150/150 设置。RoI 分数筛选严格 `> 0.001`，类别 NMS 阈值 0.5，每图最多 100 个最终框。IoU 按 CPU float32 计算。
2. 图内每个有效 GT 都单独作为一行。使用 `图片编号 + GT 顺序索引` 对齐两模型。候选与该 GT 的 IoU ≥ 0.75 时计为达标。一个候选可能覆盖多个 GT，这里的覆盖用于诊断阶段去向。
3. 固定观察阶段：RPN 输出、`person` 解码、裁剪及去背景展开、分类分数筛选后、小框筛选后（NMS 前）、完整 NMS 后、100 框预算后和最终输出。每个阶段记录候选数、达标数、最大 IoU、达标候选身份。候选为空时，最大 IoU 和最佳身份记 `null`，覆盖为 `false`，达标数为 0。
4. 对相邻阶段统计从未覆盖到覆盖，以及从覆盖到未覆盖的目标数。对每个 GT 记录首次达标和丢失的阶段。IR/Fusion 在同图同 GT 上比较。重点观察有多少目标在回归后首次达标，以及有多少已在 NMS 前达标的目标在 NMS 后失去全部达标框。
5. 记录 NMS 前最高分类分数框、最高 IoU 框的编号、分数、对 GT 的 IoU 和实际保留状态。并列最高时保留全部候选身份。若最高分框保留且达标框消失，这属于可统计的共同出现。确定逐次抑制者仍需要完整重放或内核事件证据。
