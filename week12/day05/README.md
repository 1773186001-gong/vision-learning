# Week12 Day05 · 同一目标的 IR/Fusion 配对归因

**已完成。** 对两模型在 RoI NMS 前都覆盖的同一批 **297 个目标**逐个比较。NMS 后 IR 丢失 80 个，Fusion 丢失 105 个。按已归因类别拆分，Fusion 多丢的 25 个目标中，最大的净差来自「整图最高分框直接移除零个达标框」，该类多 18 个。

## 做了什么，为什么

用 `stem + gt_index` 连接 Week11 的配对表与 Week12 两模型的逐目标归因表。先从冻结队列独立核对各模型的 97、124 个全体丢失目标，再固定共同分母 297。这样，两模型进入 NMS 时都至少有一个达标框。每个模型对每个目标只能落到「保住」「最高分框移除全部／部分／零个」「未核验」之一。

「保住」指 NMS 后仍有 IoU ≥ 0.75 的框。「零个」指目标已经失去覆盖，但其所有达标框都由其他保留框首次移除。`030397` 的两个 Fusion 目标仍为未核验，计入已知 NMS 丢失总量。

## 怎么读结果

| 类别 | IR | Fusion | Fusion − IR |
|---|---:|---:|---:|
| 保住覆盖 | 217 | 192 | −25 |
| 最高分框首次移除全部达标框 | 25 | 33 | +8 |
| 最高分框首次移除部分达标框 | 3 | 0 | −3 |
| 最高分框首次移除零个达标框 | 52 | 70 | **+18** |
| 已丢失，归因未核验 | 0 | 2 | +2 |
| 丢失合计 | **80** | **105** | **+25** |

`+8 − 3 + 18 + 2 = +25` 是同一批目标的分类计数差。只看两模型结局不一致的目标，**仅 Fusion 丢失**的 50 个中，18 个由最高分框移除全部，31 个由最高分框移除零个，1 个未核验。**仅 IR 丢失**的 25 个中，9 个为全部、16 个为零个。即使将两个未核验项都归到「全部」，该类净差最多为 10，仍低于「零个」的 18。

这里可以说「只盯着整图最高分框会漏掉主要的数量差异」。具体归因依据与原保留顺序一致的独立重放。计数差描述此验证集，暂未检验改动某个候选或算法后性能会怎样变化。

## 核验与入口

核对两套批量重放使用的冻结清单和脚本摘要一致。从逐目标记录独立重算 297 行配对与四格总量：两者都保住 167 个、仅 IR 丢 25 个、仅 Fusion 丢 50 个、两者都丢 55 个。221 行丢失记录齐全，其中 219 行通过归因核验。当天新增原始捕获读取、重放、完整前向和 checkpoint 加载均为 0。
